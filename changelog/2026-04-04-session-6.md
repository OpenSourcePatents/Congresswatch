# Session 6 — 2026-04-04

## Fix: all_bills.json exceeds GitHub 100MB file limit

### Problem
`data/bills/all_bills.json` grew to 116MB because it stored raw bill text
(including raw PDF binary bytes) alongside cleaned text, metadata, and hashes.
GitHub rejects files over 100MB, breaking the bill similarity pipeline since run 7.

### Root cause
The cache stored `raw_text` for every bill, but this field is only used once
(to generate `cleaned_text`). After cleaning, the raw text is dead weight —
often raw PDF bytes (`%PDF-1.4...`) taking up ~80% of the file.

### Solution
Stripped `raw_text` from the cache. Moved cache persistence from git to
GitHub Actions cache (`actions/cache@v4`).

### Files modified
- **run_fetch_bills.py** — Added migration step that strips `raw_text` from
  all cached bills on load. Changed incremental check from `raw_text` to
  `cleaned_text`. Removed `raw_text` from new cache entries.
- **.gitignore** — Created. Added `data/bills/all_bills.json` as safety net.
- **.github/workflows/fetch_bills.yml** — Added `actions/cache@v4` step to
  persist bills cache between runs. Removed `data/bills/` from `git add`.
