# Session 3 -- 2026-04-04

## Bug Fix: fetch.py data wipe on nightly run

**Problem:** `fetch.py` overwrote `data/members.json` from scratch every night at 01:00 UTC, wiping all finance/pipeline fields (score, total_raised, corporate_insider_signals, edgar_status, edgar_cik, fec_candidate_id, pac_contributions, etc.) that `fetch_finance.py` writes at 05:00 UTC.

**Root cause:** `normalize()` hardcoded `score: 0` and `flags: []`, and the main block wrote a fresh list with no merge against existing data.

**Fix:**
- Removed `score` and `flags` from `normalize()` — those fields are owned by `fetch_finance.py`
- Changed `"updated"` to `"data_updated"` in `normalize()` to match the field name used by `fetch_finance.py`
- Replaced the direct overwrite in `__main__` with a merge: loads existing `members.json`, updates only base Congress.gov fields (`name`, `party`, `state`, `district`, `chamber`, `photo_url`, `term_start`, `data_updated`), preserves all other fields from the existing entry
- New members (not in existing data) get added with normalize() output as-is
