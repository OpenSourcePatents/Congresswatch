# 2026-08-03 — Session 4: Senate travel pipeline + House travel cost extraction

## Summary

Two new data-acquisition capabilities, both live-source-verified before building:

### 1. Senate travel — `fetch_senate_travel.py` (new, 10th scheduled pipeline)

Senators previously had zero travel data (the House pipeline covers House gift
travel only), and the frontend's senate link
(`senate.gov/legislative/travel_disclosures.htm`) turned out to be a 404.

Source found: the Secretary of the Senate publishes ALL Rule 35 gift-rule
travel filings as a bulk XML zip at
`https://giftrule-disclosure.senate.gov/media/giftruledownloads/giftruledata.zip`
— one GET, no auth, no consent gate. Member filings carry
`ReportTitle == "Member Reimbursed Travel"` (staff filings are skipped).

- Matcher improvements over the eFD name matcher: diacritic folding
  (Luján ↔ LUJAN) and multi-word-surname tail matching (Van Hollen) — with
  them, the only unmatched filers are 6 genuinely former senators.
- Dedupe: `source_doc` URL primary + (traveler, departure, return) span key —
  amended filings get new URLs for the same trip and would otherwise double.
- Fail-loud: zero filers / zero member docs / zero matches all exit 1. The
  source is a rolling ~4-year window (HLOGA §546), so the script only ever
  ADDS trips.
- **First run: 91 trips across 41 senators, in this commit.**
- Records carry dates + document link; destination/sponsor/cost exist only in
  the scanned PDFs (Senate forms differ from House and are huge scans — cost
  extraction for Senate is future work).

New workflow: `.github/workflows/fetch-senate-travel.yml` (11:30am UTC).

### 2. House travel costs — `fetch_travel_costs.py` (new, 11th pipeline)

All 1,038 House travel records had empty `total_cost`. Feasibility was
measured on 14 sample packets (2023-2026): every packet contains a "SPONSOR
POST-TRAVEL DISCLOSURE FORM" whose Question 5 itemizes
transportation/lodging/meals/other; ~14% of packets expose the typed values
in the PDF text layer, the rest are clean typed scans suitable for OCR.

- Two-stage extraction: pdfplumber text first, tesseract OCR fallback
  (300dpi render of the first 6 pages via pypdfium2). OCR toolchain is
  CI-only — locally-absent OCR records `ocr_unavailable` and is retried in CI.
- `total_cost` = sum of the TRAVELER row (the member's own benefit);
  `family_cost` and an itemized `cost_breakdown` are stored alongside, plus
  `cost_extraction` metadata. Per-field $200k sanity cap rejects OCR garbage.
- `data/travel_cost_manifest.json` (new) tracks per-doc outcomes so settled
  docs are never re-downloaded; 40 PDFs/run (backfill ≈ 26 daily runs).
- Fail-loud: a run where every download fails exits 1.
- **Verified locally on the text-layer path: extracted $5,426.46 and
  $12,896.00 from 2 of 8 sampled packets, values matching the raw form text.**

New workflow: `.github/workflows/fetch-travel-costs.yml` (1pm UTC, installs
tesseract-ocr).
