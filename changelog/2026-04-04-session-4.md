# Session 4 -- 2026-04-04

## Added Supabase as primary data layer

All data pipelines now write to both JSON files (backup) and Supabase (primary). The frontend reads from Supabase first with JSON fallback.

### Schema (Supabase tables)
- **members** — bioguide_id (PK), name, party, state, district, chamber, photo_url, term_start, score, flags, total_raised, pac_contributions, individual_contributions, corporate_insider_signals, edgar_status, edgar_cik, fec_candidate_id, data_updated, congress_updated
- **votes** — bioguide_id + vote_id (unique), chamber, question, description, date, position, result, url
- **bills** — bioguide_id + bill_id (unique), bill_type, bill_number, title, introduced_date, latest_action, url, alec_similarity_score, alec_matched_model, alec_category, alec_source_url, donor_interest_match, donor_interest_reason
- **stats** — computed via update_stats() RPC

### Pipeline changes
- `fetch.py` — upserts base member data to Supabase after JSON write
- `fetch_finance.py` — PATCHes finance fields per member, calls update_stats RPC
- `fetch_votes.py` — upserts votes to Supabase after detail JSON write
- `run_fetch_bills.py` — upserts bills to Supabase after detail JSON write

### Frontend changes
- `index.html` — loadData() queries Supabase REST API first, falls back to data/members.json
- openProfile() fetches votes and bills from Supabase, falls back to JSON vault file
- Supabase anon key configured for read-only frontend access

### Workflow changes
- All 4 workflow files now pass SUPABASE_URL and SUPABASE_SERVICE_KEY env vars

### New files
- `seed_supabase.py` — one-time seeder to populate Supabase from existing JSON data

### No breaking changes
- All existing JSON file operations preserved as backup
- If Supabase is down or unconfigured, everything falls back to JSON seamlessly
